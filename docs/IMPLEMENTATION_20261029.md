기준: `free/v3-from-scratch`의 `2789991`. 버전 3.5. 기존 공개 공동 편집, 키 암호화, 불변 승인본, 저장 원문, 원격 처리 불명 요청의 자동 재전송 금지를 유지한다.

| 검토 항목 | 구현 |

| 원문 재처리 | 반환 모델, request/response ID, usage, 종료 사유, 비용을 다시 추출. 정산은 attempt별 멱등 처리하며 파싱 실패나 잘린 출력도 알려진 사용량은 정산 |

| 추가 파라미터 덮어쓰기 | 제공사별 고정 allowlist와 중첩 옵션 제한. 입력/모델/출력 상한/도구/출력 스키마 변경 금지 |
| 응답 종료 | 정상 완료, 제한 종료, refusal, 종료 정보 없음 구분. 유효 JSON이어도 잘린/거절 응답은 성공 처리하지 않음 |
| dispatch | 제공사별 HTTP 검사·예외 격리·전달 기록. 207 부분 실패를 API/UI에도 전달. 불명 전달은 lease 복구가 처리 |
| 서버 예산 상한 | `lab_private.server_budget_caps`; 공개 API로 올릴 수 없음. migration 시 이미 설정된 제공사 예산으로 고정하며 새 환경은 0 |

PDF 구조 검사는 `pdf-lib`로 이미지 전용 페이지 명령, Font/주석/JS/첨부 관련 객체를 확인한다. 가림의 의미와 정답 누출은 실제 공개본 미리보기에서 사람이 검토한다. 생성 provenance는 브라우저가 제공하며 서버는 원본/recipe/파일 연결 및 파일 구조를 검사한다. 기존 provenance 없는 승인 PDF는 새 버전에서 다시 준비해야 한다.

토큰은 **추정값**이다. UTF-8 bytes에 25% 여유, raster PDF 4,096/page를 적용한다. 제공사 native tokenizer나 실제 잔액 조회가 아니다. 실제 요금은 저장한 모델 단가를 기준으로 계산하며, 단가 누락 또는 원격 처리 불명은 예약을 보류한다. 서버 상한 역시 앱의 예약 한도이며 제공사 측 청구 한도 설정을 대체하지 않는다.

## 설정·복구 화면

- 키 저장 / 실제 인증·모델 응답 근거 / 텍스트 네 단계 / PDF 네 단계 / 활성화를 구분한다.
- 기본 합성 텍스트 예제 선택, 같은 모드의 진행 중 검증 중복 예약 차단, 진행/실패 이유 표시.
- 기존 프로필 복제 후 새 설정 등록. 과거 실험의 모델·가격은 유지하고 새 설정은 다시 검증.
- 실행 전 한도/키/승인/모델/예산/최대 예약액 점검. 후속 후보 크기는 실행 직전에 다시 검사.
- 저장 응답 재파싱, 미전송 차단 복구, 제공사 미처리 확인 후 재예약, 실패 확정 화면.
- 제공사 잔액은 **사용자 직접 확인 기록**임을 명시하고 24시간 유효기한 표시.
- 작업별 공개 단계·추가 지시·스키마·첨부 공개 PDF를 포함한 전송 입력 미리보기.

## 재현성·분석·내보내기

- DB에 신뢰하는 기본 프롬프트/스키마 bundle을 저장하고 계획 생성 시 복사한다. 실행은 해당 snapshot을 사용하며 지원하지 않는 실행 버전은 차단한다. 요청마다 protocol hash, execution version, wire hash와 실제 모델/usage를 남긴다.
- 공통 반복은 `plan_id + revision_id + repeat_index`로 묶는다. 계획 간 불완전한 결과를 임의로 하나의 반복에 합치지 않는다.
- 사람 검토 및 표집 기록을 선택 run/idea 범위로 제한한다. 새 독립 채점도 선택 계획 범위만 포함한다.
- `metrics-v5`로 분석 버전을 통일. source analysis hash와 exported snapshot hash를 별도 표시.
- `research.xlsx` 직접 다운로드. ZIP의 작은 파일은 원래 파일명으로 저장. 큰 분할 파일은 포함된 `reassemble-export.py`로 SHA-256을 검사하며 복원.
- 논문별 공유 허용 설정, 외부 공유 포함/제외 목록. 외부 파일에서 원본/비공개 기준/원문 요청/검토자 신원을 제거하며 모델 응답과 파생 점수는 보존한다.
- 논문별 결과, 실패/결측 건수, 논문 단위 95% percentile bootstrap(2,000회, 고정 seed). 한 논문이면 구간 없음. null을 0으로 채우지 않는다.
- 브라우저 임시 ZIP/Excel 정리 버튼과 저장 공간 오류 안내. 연구 결과 ZIP은 전체 복구용 백업이 아님.

## 연구 과제

기존 `idea` 흐름은 유지한다. 새로운 문항에는 `task_type`, `decision_point=P1..P5`와 별도 비공개 채점 기준을 저장한다.

| 유형 | 실행·채점 |
| --- | --- |
| generation | 실험 설계·근거·위험 응답. 문항별 필수 조건·부분점수·허용 답에 대한 사람 채점 충족률 |
| discrimination | 원본/결함 대안. 계획·문항·반복을 기준으로 A/B 배정, 순서 교환도 별도 run. 정답률 및 양쪽 순서 모두 정답인 블록 |
| anchoring | 정상/결함 앞 단계 각각 별도 run. 지적·수정·추종/정상 보존의 사람 판정 |
| review | 공개 설계에 대한 심사 지적. 제출본/리뷰 위치/저자 답변/수정/확정·부분·제기 근거표. 확정 지적 recall과 사람 판정 오지적 비율 |

ML 문항은 K 후보 생성·AI 상호 채점과 다른 과제이며 조건별 응답 1회를 사용한다. 기존 활성 모델의 일반 JSON/PDF 검증 후, 각 새 과제의 실제 소규모 예비 실험이 필요하다. 사람이 아직 채점하지 않은 값은 결측으로 표시한다.

독립 채점은 검토자별 **별도 Excel**로 내보내고 다시 가져온다. 생성자 이름/AI 점수/다른 검토자의 판정은 파일에 넣지 않는다. 문항 hash 검증, 점수 범위/근거 필수, 첫 판정 보존, 수정 사유 필수, 두 명의 최초 판정 후 합의 저장을 지원한다. 기존 idea 실험도 후보별 유용성·일치도 독립 파일을 지원한다. 이 파일은 기준을 함께 보여주는 오프라인 검토이며 기존 AI의 blind peer 점수를 대체하지 않는다.

공용 로그인 하나를 두 사람으로 간주하지 않는다. 검토자 코드는 팀이 관리하는 **자기 신고 식별자**이며 인증된 개인 계정이 아니다. 독립 작업의 실제 수행을 팀이 확인해야 하고 가져오기에서도 이를 확인한다.

논문 관리 정보에는 최초 공개일, 출처, 제출본/최종본 버전, 선정·제외 사유, 담당자를 추가했다. 날짜와 정답 근거를 자동으로 사실 확인하지 않는다.

## 검증과 운영 경계

`npm run check`, `npm test`, `npm run test:integration`, `npm run build`, `npm run bundle:edge`, Deno check 및 Playwright 테스트를 사용한다. API 테스트는 모의 HTTP 응답이다. 실제 제공사 키/크레딧/모델 접근 및 유료 성공은 배포 후 별도 확인해야 한다.

`npm run verify:live -- --allow-paid --api-url https://PROJECT.supabase.co --profile UUID`는 배포된 앱에서 유료 검증 4회를 예약하고 request ID/usage 근거를 `test-results/live-smoke.json`에 저장한다. 자동 CI에서는 실행하지 않는다. PDF는 `--mode pdf --revision UUID`를 추가한다. 관련 없는 계획을 먼저 일시정지한다.
