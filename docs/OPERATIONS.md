# 운영과 복구

## 실험을 시작하기 전

분기점의 공개 입력과 기준 아이디어 위치를 다른 팀원이 교차 확인합니다. PDF 원본은 모델에 보내지 않고, 실제 raster prepared PDF만 전송합니다. 유용성에는 기준 아이디어를 넣지 않습니다. 설정을 바꾸려면 새 프로토콜·프로필·분기점 버전을 만들고 새 계획을 시작합니다.

## 단계 오류

진행 상황에서 job을 열면 오류 유형, 요청/응답 시각, 실제 전송 입력, 원문 asset을 확인할 수 있습니다. 화면에 모델이나 usage가 없으면 실제 반환값이 없는 것이며 임의의 성공값을 채우지 않습니다.

- 키·결제·권한·spend 한도 오류: 설정을 해결하고 관리자가 제공사 차단을 해제합니다. 자동 루프를 돌리지 않습니다.
- 일시적인 429: Retry-After 또는 제한된 backoff를 적용하며 최대 4시도 뒤 확인을 요청합니다. 일일 한도 복구 시각을 모르면 자동 재시도하지 않습니다.
- 거부·잘림·잘못된 JSON: 원문을 보존하고 확인 필요로 둡니다. 조용히 JSON을 보정하지 않습니다.
- `saved_response_processing`: 같은 단계 재시도는 저장 응답을 다시 해석합니다. 제공사에 다시 보내지 않습니다.
- `unknown_remote`: 원격 결과를 알 수 없습니다. 동기 inline 경로에서 원격 조회가 지원되지 않는다고 명확히 표시합니다. 중복 실행·과금 위험에 동의한 명시 재시도만 새 시도를 만듭니다.
- 브라우저·웹 종료: 클라우드 worker가 계속 처리합니다. worker 종료 시 lease 90초·heartbeat 15초와 저장된 응답으로 복구합니다. 플랫폼 강제 종료 시 원격 처리의 정확히 한 번 실행을 보장하지 않습니다.

키·DB URL·요청 본문·예외 원문이 서버 로그에 출력되지 않도록 했습니다. 오류 신고는 job ID·request ID·표시된 오류 유형을 사용합니다.

## 내보내기와 분석

기본 분석은 선택한 최신 본실험, 없으면 예비실험 중 API 자료입니다. 다른 입력 방식·프로토콜·모델 프로필·cohort는 조건 그룹을 나눕니다. 공통 비교는 지표별 적격 분기점×반복의 교집합을 사용합니다. 반복 → 분기점 → 논문 순으로 평균하여 논문 수가 다른 조건에 불필요한 가중치를 주지 않습니다. 판단 불가·누락은 0점으로 바꾸지 않습니다.

Excel은 10개 시트와 원문 식별자를 유지하며, 긴 본문은 별도 파일에 보존합니다. 텍스트가 `=`, `+`, `-`, `@`로 시작해도 Excel 수식으로 실행되지 않습니다. ZIP 생성과 summary는 같은 DB snapshot에서 계산합니다. 생성 대기 중인 응답을 받기 위해 AI를 추가 호출하지 않습니다.

## 백업

설정 → 운영 → 연구 백업 생성에서 요청합니다. worker는 한국시간 03:00 이후 당일 백업을 예약합니다. 성공 백업은 Supabase private lab-exports와 worker의 영속 디스크에 보관합니다. 새 파일 hash를 검증한 뒤 최근 3개 로컬 복사를 유지합니다. 실패한 당일 자동 백업은 30분 이내 반복하지 않습니다.

40MiB를 넘으면 manifest와 모든 part를 다운로드합니다. 파일 이름 순서의 part를 binary로 연결한 뒤 manifest의 전체 SHA256을 대조할 수 있습니다. 앱 내부 복원은 각 part의 workspace·종류·크기·SHA256을 확인하고 자동으로 연결합니다.

서버 비밀값과 API 키는 연구 백업에 포함하지 않습니다. master key와 API 키·Google OAuth 설정은 별도의 안전한 보관 절차가 필요합니다. 같은 Supabase 프로젝트 안의 복사만으로 프로젝트 삭제에 대비했다고 주장하지 않습니다. 백업을 별도로 다운로드하고 보관을 확인해야 합니다.

## 복원

설정 → 운영 → 백업 선택 → 새 공간으로 복원 → manifest·행 수 확인 후 복원을 실행합니다. 기존 공간을 덮어쓰지 않으며 새 비활성 공간과 새 UUID를 만듭니다. 원본·prepared·요청/응답 파일을 새로운 경로에 복사하고 hash를 확인합니다. 표시 순열 seed와 최초 사람 판단은 보존합니다. 계획은 일시정지하고, 재생성 가능한 export/backup 작업은 취소 상태의 이력으로 남습니다.

복원 공간을 운영 대상으로 바꾸는 버튼은 제공하지 않습니다. 운영 전환은 관리자가 정지·검수·원본 보관 후 별도로 수행해야 합니다. DB 연구 행만 복원하고 Storage도 복구했다고 표시하지 않습니다.

```bash
python -m lab.cli backup --workspace <uuid>
python -m lab.cli restore --archive <backup.zip> --target-new-workspace
```

Supabase 운영 DB 백업 플랜, 실제 worker 강제 종료·디스크 보존·외부 보관 검수는 배포 후 실제 계정에서 확인합니다.
